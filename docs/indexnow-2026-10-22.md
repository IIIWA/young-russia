# IndexNow для young-russia.ru

Установлено и проверено 22.10.2026. CMS подтверждена пользователем: Nuxt.

**Статус: IndexNow установлен на хостинге. Яндекс подтвердил приём тестового уведомления ответом HTTP 200. Первый запуск по расписанию проверен.**

[Машиночитаемый отчёт проверки](indexnow-release-2026-10-22.json).

## Выбранный способ

Сайт публикуется как статические HTML-файлы. Небольшое задание на хостинге раз в пять минут сравнивает содержимое опубликованных страниц и отправляет новые, изменённые и удалённые адреса в `https://yandex.com/indexnow`. Яндекс обменивается уведомлениями с остальными участниками IndexNow. Установка не требует запущенного Nuxt, npm-пакетов, CMS-плагина или платного API.

После первого обнаружения изменения предусмотрена пауза пять минут: обычная задержка уведомления составляет 5–10 минут. Это снижает вероятность отправки адресов во время незавершённой публикации.

## Что установлено

- Файл подтверждения в `public/<ключ>.txt`. Nuxt копирует его в корень сайта при будущих сборках. При текущей установке загружается только этот новый текстовый файл.
- `scripts/indexnow/indexnow.py`: сравнение страниц, очередь, отправка и повтор при ошибке.
- `scripts/indexnow/install.py`: отдельная установка без загрузки `dist/` и без замены существующих страниц.
- `scripts/indexnow/connect.mjs`: подключение существующим SSH-ключом после свежего подтверждения пользователя.
- `scripts/indexnow/test_indexnow.py`: проверки поведения очереди и запросов.

На хостинге служебные файлы размещены вне каталога сайта:

```text
/var/www/u3013321/data/automation/young-russia-indexnow/
  indexnow.py
  config.json
  state.json
  state.lock
  run.log
  installation.json
```

## Поведение

Первый запуск сохраняет исходное состояние опубликованных страниц без массовой отправки старых URL. Для проверки подключения отправляется один URL главной страницы.

Далее отслеживаются адреса из опубликованного `sitemap.xml`. Добавленную страницу нужно включить в карту. Удалённую страницу нужно убрать из карты и обеспечить корректный ответ 404/410 либо нужный редирект на хостинге. Сам протокол передаёт только URL; окончательное состояние поисковик определяет при обходе.

Скрипт сравнивает видимый HTML, заголовки, описание, каноническую ссылку и значимые атрибуты. Смена служебных идентификаторов сборки, JavaScript и CSS не вызывает отправку всего сайта. Закрытые через HTML `noindex` страницы исключаются. Произвольные заголовки `X-Robots-Tag` и сложные правила `robots.txt` отдельно не анализируются; сейчас публичный robots.txt разрешает обход сайта.

При пустой/повреждённой карте или отсутствующем HTML, на который ссылается карта, запуск прерывается без массового объявления удалений. Изменения, произошедшие во время сканирования, переносятся на следующий запуск. Очередь хранится вне сайта и переживает его публикации. Успешный HTTP 200 убирает отправленные адреса из очереди. HTTP 202 сохраняет их для повторной проверки; ошибки вызывают повтор с увеличивающимся интервалом.

## Установка и подтверждение результата

Перед SSH требуется свежее подтверждение пользователя, что он сейчас на своём сервере. Первичная установка выполнена следующей командой из проекта; повторно запускать её для уже работающей установки не требуется:

```powershell
node scripts/indexnow/connect.mjs --server-confirmed
```

Установщик проверяет наличие Python 3.6+ и доступа к пользовательскому crontab, отказывается перезаписывать прежнюю установку или возможный существующий ключ IndexNow. Сохраняет прежнее расписание в отдельной резервной папке вне сайта, добавляет файл ключа и службу, сохраняет исходное состояние страниц, отправляет тестовый URL и добавляет одну строку расписания, сохраняя другие задания.

Первая разрешённая попытка SSH выявила системный Python 3.6.8. Установщик остановился на проверке версии до любых изменений. После адаптации для Python 3.6+ установка и настоящая отправка прошли без установки ПО на сервер.

При неудачной установке собственная строка расписания и собственный публичный ключ убираются; диагностическая папка сохраняется. Чужие задания и опубликованные страницы не заменяются.

Установщик остаётся в том же SSH-сеансе до шести минут, чтобы увидеть первый фактический запуск задания. Событие `cron_verified` подтверждает запуск, `cron_not_observed` означает, что выполнение по расписанию ещё не подтверждено. HTTP 200 подтверждает приём уведомления, HTTP 202 означает ожидание проверки ключа. Ни один из этих ответов не гарантирует включение страницы в поиск.

## Отключение

Убрать из пользовательского crontab только строку с комментарием `# young-russia-indexnow`. Файл ключа и папку состояния можно сохранить для последующего возобновления. При удалении ключа его также нужно убрать из `public/`, чтобы следующая сборка не вернула его на сайт. Другие строки расписания не восстанавливать вслепую из старого снимка.
