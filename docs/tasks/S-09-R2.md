## Действия и файлы

1. Сверить текущий HEAD и рабочую папку с принятым составом S-09-R1A и решением пользователя. Если появились посторонние изменения, заново определить точный разрешённый состав; ничего не сбрасывать и не удалять.
2. Добавить в index только принятые пути, включая необходимые документы управления. Не форсировать добавление игнорируемых внутренних заметок или `AGENTS.md` без отдельного решения по ним.
3. Проверить фактический staged diff и `git diff --cached --check`, повторить подходящие проверки для изменившихся после ревизии файлов. При конкретной проблеме сборки подготовить отдельное исправление; не обходить проверку ради коммита.
4. Создать локальный коммит принятой партии и отправить в согласованную ветку после проверки её назначения. Не использовать force push, amend чужого коммита или автоматическое разрешение конфликтов за счёт потери данных.
5. Проверить удалённый SHA. При отсутствии доступа сохранить готовый локальный результат и точно назвать непроверенную/невыполненную часть; локальный коммит не считать подтверждением push.

Запись: Git index/локальный коммит, согласованная удалённая ветка и `docs/reviews/S-09-R2.md`. Самостоятельное редактирование кода сайта, SSH и изменение опубликованных страниц в задачу не входят.

## Приёмка

- Состав коммита совпадает с принятой партией, исключения сохранены и объяснены.
- Есть SHA коммита, результаты staged-проверок и подтверждённый удалённый SHA либо конкретный блокер push.
- Остаток рабочей папки описан; приватные данные не добавлены.
- Состояния Git и опубликованного сайта записаны раздельно. Управляющий чат обновляет S-09, после чего предлагает следующий запуск.
