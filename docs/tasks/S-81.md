## Схема JSON

Один файл на район `data/research/vk-notes-2026-10-28/<district>.json`. Обязательны:

- `schemaVersion: 1`, `taskId`, `checkedOn: "2026-10-28"`, `district`, `sourceNote: {path, snapshotPath, sha256, lineCount, kind: "user_supplied_vk_copy"}`.
- `organizationFacts`: отдельные сведения учреждения с источниками и условиями; `clubs`: одна запись на каждый исходный клуб каталога, `additionalRecords`: дополнительные/неоднозначные записи отдельно.
- Каждая запись клуба: `name` (точно из каталога), `baselineMatch`, `noteCoverage` (`mentioned`, `organization_only`, `not_found`), `sourceRefs`, `activities`, `scheduleRecords`, `links`, `restrictions`, `questions`, `officialComparison`.
- `sourceRefs`: `{sourceNote, startLine, endLine, quote, url?}`; у извлечённых фактов сохранять такое основание. Активность: `{name, description?, age?, funding?, sourceRefs}`. Расписание: `{activity, slots:[{day,time,group?,room?}], period, currentness, fundingEvidence, sourceRefs, evidenceId?}`. Поля можно расширять без потери оригинала.
- `links`: `{url, kind, label?, activity?, sourceRefs}`. Для не сообщества честно указывать вид.
- `evidence`: `{id, type, sourceUrl?, localPath?, sha256?, sourceRefs, reviewStatus, limitations?}`; `issues`, `publicCandidates`, `counts`. У `publicCandidates` обязательно причина готовности/откладывания, а не автоматическое утверждение.

Приёмка: все факты прослеживаются до строк/страницы/изображения; все исходные клубы учтены ровно один раз; время валидно; каждый медиаисточник имеет реальный статус просмотра; исходные заметки не изменились. Отчёт не должен преувеличивать полноту источников.
