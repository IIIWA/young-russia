## Действия и файлы

1. Прочитать Git diff, новые файлы, `.gitignore`, текущие источники, конфигурацию, генераторы и отчёты выпусков 22–24 октября. Использовать сводку и группы файлов вместо вывода тысяч имён в чат.
2. Сопоставить код/данные и `dist/` с отчётами. Для каждой группы назвать назначение, свидетельства проверки и предполагаемое включение в коммит. Проверить закрытые маршруты «Адмиралтейца», сохранённые прототипы и материалы гидов S-56, ожидающих согласования.
3. Выделить потенциально приватные материалы, локальные источники, рабочие палитры, кэши, резервные копии и секреты. Содержимое секретов не выводить. Не менять исключения Git автоматически.
4. Проверить `git diff --check` для предлагаемых исходников, синтаксис изменённых генераторов и `npm run check` на существующей сборке. Если требуется пересборка или исправление, описать конкретную причину и необходимый отдельный этап; эта ревизия не меняет сайт.
5. Зафиксировать, что известно о локальных файлах, HEAD, локальной `origin/main`, GitHub и опубликованном выпуске. Внешний read-only Git-запрос допустим, если доступен существующий способ авторизации; отсутствие сети записать как непроверенное состояние. SSH не входит в задачу.

Разрешённая запись: `docs/reviews/S-09-R1.md` и `docs/reviews/S-09-R1.json`; временные свидетельства в `outputs/S-09-R1/`. Каталог, генераторы, `dist/`, прототипы, index и история Git остаются входными данными ревизии.

## Результат и приёмка

- В отчёте есть дата, HEAD, актуальные количества путей и группы изменений с причинами включения/исключения.
- JSON содержит точные пути предлагаемой партии и отдельные списки исключений и нерешённых случаев. Каждый путь обоснован, `git add -A` не используется как способ отбора.
- Проверки и оставшиеся риски подтверждены результатами; внутренние данные не раскрыты в отчёте.
- История публикаций сопоставлена с Git; недоказанное совпадение не объявлено проверенным.
- Управляющий чат может принять состав партии либо назвать конкретные требуемые исправления. Коммит, push и новая публикация не выполнены.

После отчёта исполнитель останавливается. Управляющий чат проводит приёмку, обновляет реестр и предлагает S-09-R2 по отдельной команде.
