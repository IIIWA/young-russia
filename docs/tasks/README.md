# Работа управляющего чата и исполнителей

Принято 25.10.2026. [План](../../PLANS.md), [очередь](../../TASKS.md), [единый реестр](../../YoungRussiaOBS/СТАТУС-САЙТА-И-ЗАДАЧИ.md).

## Запуск и контроль

1. Управляющий чат готовит самостоятельное задание с исходными файлами, ограничениями, результатом и критериями приёмки.
2. Пользователь запускает работу. По постоянному разрешению от 29.10.2026 управляющий может сам создавать чаты и назначать ограниченные подзадачи внутри этой работы; новые несвязанные задачи остаются подготовленными.
3. Управляющий чат проверяет зависимости и доступные средства. Для отдельного чата сначала находит проект в списке проектов. В сообщение исполнителю включается полный контекст задания и правила; ссылки на локальные документы сопровождаются абсолютным путём рабочей папки.
4. По умолчанию используется текущая локальная папка последовательно. Worktree выбирается только по явному запросу пользователя. Нельзя направлять двух писателей в одни файлы. До ревизии незакоммиченной партии запрещено считать новую worktree копией текущей рабочей папки.
5. В очереди сохраняются настоящий ID чата, разрешённые действия и файлы. Для самостоятельных исполнительских задач используются постоянные проектные чаты с ограниченной областью записи.
6. Управляющий чат читает ход и результат уже запущенной задачи, проверяет критерии и свидетельства. Новое рабочее сообщение или поручение на исправление отправляется при наличии соответствующего разрешения пользователя.
7. После проверки управляющий чат отмечает «Принято» либо перечисляет конкретные несоответствия. Обновляются реестр и пересекающиеся пункты доски 90 дней. Следующий этап ожидает новой команды.

Поручение может назвать ID или описать нужный результат: управляющий присваивает ID и ограничивает область исполнителей. Постоянное разрешение на оркестрацию от 29.10.2026 покрывает рабочие уточнения и исправления в пределах уже порученного результата. Git, публикация и новые несвязанные задачи определяются объёмом пользовательского поручения; свежее присутствие перед SSH проверяется отдельно по AGENTS.md.

## Скиллы и инструменты

Новых установок для этой схемы не запланировано. На 25.10.2026 текущий сеанс предоставляет перечисленные ниже возможности. Наличие инструмента не доказывает доступ к конкретному аккаунту, репозиторию или серверу; доступ проверяется при запуске соответствующего задания.

| Средство | Для чего используется | Состояние и границы |
| --- | --- | --- |
| Инструменты Codex для проектов и чатов | Найти проект, создать отдельный чат по команде, читать результаты, ждать завершения, передавать разрешённое задание | Предоставлены в сеансе; при подготовке плана вызовы создания и отправки не выполнялись |
| Локальные файловые команды и Git | Читать исходники, сравнивать изменения, выполнять проверки, сохранять согласованную партию | Доступны; изменения Git-истории и push определяются отдельным заданием |
| Браузер | Проверять страницы, интерфейс, доступные официальные источники и кабинеты | Доступен; URL локального просмотра проверяется перед выдачей |
| `clean-typography` | Русский видимый текст сайта | Уже доступен; применяется при правках текста на страницах |
| `pixel-perfect-layout` | Вёрстка по конкретному референсу | Уже доступен; подключается к заданию с образцом |
| `site-speed` | Производительность и проверка перед сдачей сайта | Уже доступен; используется при соответствующем этапе |
| `deploy-server` | Публикация и проверка выпуска | Уже доступен; перед новой SSH-сессией нужно свежее подтверждение присутствия пользователя на сервере |
| `openai-docs` и Plugin Management | Проверить возможности Codex, подходящие интеграции и их ограничения | Уже доступны; не устанавливают дополнительные средства в рамках планирования |
| `pdf` и `spreadsheets` | Источники расписаний в PDF, CSV и XLSX | Уже доступны; используются по формату исходного материала |

Скилл задаёт рабочую процедуру, MCP предоставляет действия или доступ к данным. Для управления достаточно существующих возможностей и правил в проекте; отдельный MCP-менеджер не требуется. Основание: [официальная документация OpenAI](https://developers.openai.com/plugins/concepts/plugins).

GitHub-интеграция может рассматриваться отдельно, если понадобятся операции с PR или issues, которых нельзя выполнить существующими средствами. MCP для аналитики рассматривается только после проверки уже подключённых API. Новый сервер, плагин или платный сервис не добавляется ради названия роли.

## Формат результата исполнителя

- ID задания, фактическая папка и исходная Git-ревизия.
- Что сделано и какие файлы изменены.
- Свидетельства по каждому критерию, команды проверки и их результат.
- Что осталось неизвестным, какие внешние ответы нужны.
- Отдельные состояния: локальные файлы, локальный Git, GitHub, опубликованный сайт.
- Ссылка на отчёт и рекомендуемый следующий шаг, который ещё не запущен.

Не включать токены, пароли, ключи, приватные контакты и необработанные внутренние заметки в публичный отчёт. `AGENTS.md` и большая часть Obsidian сейчас исключены из Git; присутствие локального файла не означает его передачу в новый checkout.
