## Данные и проверка

Для каждого клуба: название, адреса, соответствие старой карточке, официальная страница, VK клуба с URL страницы-основания, отдельные сообщества направлений, бесплатные и платные предложения, возраст, даты и ограничения. Для расписания: точное название направления, дни, часы, группы/помещения при наличии, источник/тип/страница/период. Не выдумывать окончания по старту; режим клуба и часы сотрудника не считать расписанием секции. Одноимённая платная часть не отменяет бесплатную. Летние/старые графики отмечать архивными. Прямая проверка VK не входит в задачу: сохранять ссылки с официальных страниц по прежней просьбе пользователя работать без прямого VK.

Документы и изображения скачивать и анализировать. Для сканов необходим визуальный просмотр: скачивание и OCR сами по себе не считаются просмотром. Вести перечень URL, SHA256, локальных путей, страниц, результата анализа и статуса визуальной проверки. Искать полноразмерные изображения, не читать 15x15 превью. Логотипы, баннеры и несвязанные новости отделять от кандидатов расписаний. Сохранять нераспознанные ячейки/недоступные источники как конкретные вопросы.

Записи `activitySchedules` должны содержать `activity`, `slots` (`day`, `time`, `group`, `room`), `sourceUrl`, `sourceType`, `period`, `currentness`, `fundingEvidence`. Сырые фрагменты без уверенной связи хранить отдельно. В конце самостоятельно сверить покрытие всех исходных клубов и оставить точные непокрытые вопросы; дать краткий итог с файлами.
